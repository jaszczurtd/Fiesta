# VP37 viewer: configuration and technical reference

[Polski](REFERENCE.pl.md) · [Viewer guide](README.md)

## VS Code in the ECU workspace

Open `src/ECU` as the VS Code folder. With CMake and a native C/C++ compiler
available (MSVC Build Tools on Windows), run **Tasks: Run Task -> VP37: Live
viewer**. Its dependencies configure and build Release in
`.build/vp37-viewer`, then rebuild and upload the ECU **BENCH** variant using
the project's selected assembly and verified device identity. After upload,
the viewer starts the persistent serial monitor and captures its output. The task works on
Linux and Windows, including workspace paths with spaces. It uses the pinned
HAL dependencies and does not require a browser for the build.

The task appends timestamped telemetry to `src/ECU/.build/vp37.log` and follows
that file. No separate collector is needed. To choose another recording path,
edit the argument after `--log` in
[`src/ECU/.vscode/tasks.json`](../../src/ECU/.vscode/tasks.json) to select your
log. Keep the path as one JSON string, with no extra shell quotes;
on Windows use `/` or escaped `\\` separators.

After `Connected to ...` and its separator, the terminal prints the live URL
and instructions for Chrome and VS Code. Open `http://127.0.0.1:8037/live`
in a web browser, or run **Open Integrated Browser** from the VS Code command palette
and paste that URL. The message uses the configured HTTP port and appears
again after reconnecting. Keep the task running while viewing data.
Move the browser tab to a separate editor group to keep
the code visible. New samples appear automatically; a new connection receives
no earlier history.

Stop the server with Ctrl+C in its terminal or **Tasks: Terminate Task**.
Closing the browser tab leaves the server running. Stop it before starting
another viewer on ports 8037/8038; a port conflict fails startup. To use other
ports, edit `--port` and `--ws-port` in the task and the HTTP URL in your
shortcut. A build or configure error stops the dependency chain; fix the
reported error and run the task again.

## Keyboard shortcuts

For keyboard access, open **Preferences: Open Keyboard Shortcuts (JSON)**
and add these entries to the existing user array:

```json
{
  "key": "ctrl+shift+f11",
  "command": "workbench.action.tasks.runTask",
  "args": "VP37: Live viewer"
},
{
  "key": "ctrl+shift+f12",
  "command": "simpleBrowser.api.open",
  "args": "http://127.0.0.1:8037/live"
}
```

Ctrl+Shift+F11 starts the task; Ctrl+Shift+F12 opens the view once the server
is ready. These are user bindings: `.vscode/keybindings.reference.json`
is a generated reference, not an active keybinding file. Project
synchronization preserves the viewer tasks and their log arguments; it
regenerates that reference file.

## Serial capture

The monitor retains its port ownership and reconnect behavior, including
release for another upload. Stop the task to stop capture and the server.
Starting it again appends to the log and repeats the BENCH build/upload.
Capture starts reading at the existing end of the log, before appending its
session marker, so earlier sessions do not delay current samples.
`serve --log PATH` alone still follows a file produced by an external collector.
Add `--monitor-project /path/to/ECU` to capture through the monitor configured
in that project's `.vscode/settings.json`. Capture removes console ANSI codes,
adds host timestamps, preserves the `ECU:` prefix and flushes each complete line.
An unfinished line at exit is discarded. Only one viewer may capture to a
given log; the adjacent `.capture.lock` file may remain after exit.
A NUL byte or a console line longer than 65408 bytes terminates capture and
the server with an error. The limit reserves space for the timestamp/prefix;
previous complete lines remain in the log.

## View limits

| Retained data | Limit |
| --- | --- |
| Numeric rows | 4096 each for `C` and `IPULSE`; 512 each for `CFG` and `ADJ` |
| Field definitions | 256 catalog entries; unknown keys are counted and discarded |
| Events | 256, with at most 256 characters each |
| Traces | Four completed dumps and one pending dump; at most 2048 rows per dump |
| Paused view | One additional snapshot, at most the live row limits or one trace |

Row caps can shorten the retained window at high input rates. `IWAVE` is
transported but has no live panel or browser buffer. The offline viewer keeps
its existing export rules.

## HTTP server and WebSocket protocol

`/api/fields` exposes the shared field catalog. `/api/status` returns status JSON, and
`/live-assets/` serves the bundled live assets. With `--site`, offline pages
use their own `/assets/` files, including sites generated by older viewers.
Static files must be smaller than
512 KiB; files at or above this limit return HTTP 413. Paths outside the selected roots are
rejected. HTTP and WebSocket each allow four clients.

HTTP requests and WebSocket handshakes each use a 4096-byte buffer for the
request line and headers. The largest accepted request is 4094 bytes; at
4095 bytes the server rejects it with HTTP 413. A longer request may instead
end with a TCP reset if unread bytes remain when the server closes the socket.

The WebSocket endpoint is `ws://127.0.0.1:8038/ws`. Protocol version 1 sends:

| Message | Meaning |
| --- | --- |
| `hello` | `protocol`, current `epoch`, next batch number `next`, log `present` and `ws_port`. |
| `reset` | The same fields after the log appears, disappears, is truncated or replaced. Start a new display segment. |
| `samples` | `epoch`, increasing `seq` and `records`. Each record has `kind`, `t` in seconds, and numeric `values` or event `text`. Missing/non-finite numbers are JSON `null`. A control record with `restart: true` starts a new display segment. |

Batches normally leave every 40 ms, or earlier when they reach 32 KiB. Records
use MCU time where available, with the mapping described below. `HOST`, `TEST`
and other VP37 messages, including trace completion, retain their text. This
does not add interpretation of calibration records.

A connection receives subsequent batches, without replaying earlier history.
Batch numbers expose gaps. On reconnect, start from `hello`; a stopped server
starts a new stream. A client that cannot accept a complete frame is disconnected
without queuing or retrying a partial frame. Client data messages are rejected;
the endpoint only publishes measurements.

The reader preserves incomplete lines at EOF and discards them on a detected
file change. Detection uses file identity, size and the last 64 consumed bytes.
An in-place rewrite that restores the same bytes and size between polls cannot
be distinguished from append-only input. Use atomic replacement for log rotation.
Each poll reads at most 64 KiB. Lines are limited to 64 KiB, numeric records to
256 distinct fields, and encoded records to 32512 bytes. Exceeding a limit or
encountering a read error terminates the command with an error. A missing file
is waited for. Parser history and client queues do not grow with log length.

## Parser

`src/telemetry.h` exposes `TelemetryParser::feed()` and `finish()`. Chunks may
end anywhere in a line; only complete lines are delivered before `finish()`.
The limit is 64 KiB per line. Errors terminate that reader; discard its partial
output and create another reader after a file replacement or truncation.

The default time axis retains collector timestamps for compatibility with
recorded metric windows. The optional MCU mode unwraps `us` and places delayed
`T`, `IPULSE` and `IWAVE` samples relative to control records. Backward control
timestamps start a new epoch. A mapped control time more than five seconds
from host time also reanchors the clock and marks that record with `restart`.
This permits serial buffering while detecting resets that resemble rollover.
Consecutive control observations must be less than 2^31 microseconds apart.
A reset within the host-time tolerance of a genuine rollover remains ambiguous
without an explicit restart marker. Lines without `us` retain collector time.
Numeric fields from every `CFG` are retained separately from revision summaries.

`parse_log()` uses the same reader. The line splitter and timestamp arithmetic
are C11; the existing recording model and page generator remain C++17. The
parser version invalidates older caches when its output changes.

The callback constructor streams one record at a time without retaining a
recording. Its borrowed values are valid only during the callback; an error
returned by the callback terminates the reader. Offline parsing is unchanged.
Interpretation of calibration records (`CAL`) is not implemented yet. Existing unknown fields
and line kinds are reported by the offline viewer.

The viewer tests also run through the ECU host-test build, including its local
gate and CI. They use only the independent files in `tests/fixtures/`.
